# Деплой на Amvera Cloud

Пошаговая инструкция для «Кирилл & Елизавета». Всё делается мышкой, примерно 20 минут.

---

## Что понадобится

1. Аккаунт на [amvera.ru](https://amvera.ru)
2. Архив `amvera-upload.zip` из корня проекта
3. Пара значений, которые вы уже использовали (см. шаг 5)

---

## Шаг 1. Создать базу данных PostgreSQL

1. В личном кабинете: **Создать приложение → База данных → PostgreSQL**
2. Заполните четыре поля — **запишите каждое значение**, все понадобятся:

   | Поле | Что вписать |
   |---|---|
   | Имя создаваемой БД | придумайте, например `wedding` |
   | Имя пользователя | придумайте, например `wedding_user` |
   | Пароль пользователя | придумайте пароль |
   | Размер кластера | 1 реплики достаточно |

   ⚠️ Имя `postgres` платформа не разрешает ни для базы, ни для пользователя.
   ⚠️ Регистр букв в логине и пароле имеет значение.

3. Нажмите «Завершить» и дождитесь статуса «PostgreSQL запущен»

### Как собрать строку подключения

Готовой строки Amvera не показывает — её собирают из четырёх значений
и внутреннего домена кластера.

**Внутренний домен** (для подключения из вашего приложения на Amvera)
находится на странице **Инфо** вашей базы и выглядит так:

```
amvera-<ваш-логин>-cnpg-<имя-проекта-базы>-rw
```

Для вашего случая (проект называется `wedding-db`) это, скорее всего:

```
amvera-deeod-cnpg-wedding-db-rw
```

Суффикс `-rw` означает чтение и запись — он и нужен.
(Есть ещё `-ro` — только чтение, и `-r` — любая нода; они не подходят.)

**Готовая строка подключения** собирается по шаблону:

```
postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@amvera-deeod-cnpg-wedding-db-rw:5432/ИМЯ_БАЗЫ
```

Подставьте свои значения из пункта 2. Пример, как это выглядит
с вымышленными данными:

```
postgresql://wedding_user:S3cretPass@amvera-deeod-cnpg-wedding-db-rw:5432/wedding
```

4. **Скопируйте собранную строку** — понадобится на шаге 5

> **Заметка про порт:** порт 5432 стандартный для PostgreSQL, менять не нужно.
>
> **Заметка про SSL:** Amvera по умолчанию использует режим `prefer`, отдельно указывать не требуется.

## Шаг 2. Создать приложение

1. **Создать приложение → Обычное приложение** (не база данных)
2. Имя, например `wedding-invite`
3. Регион — любой российский

## Шаг 3. Залить код

> **Не заливайте `node_modules` и `.next`.** В прошлый раз ушло 526 МБ вместо 7 МБ — сборка шла вдвое дольше. Если загружаете через интерфейс, удалите эти две папки перед загрузкой (или используйте git — `.gitignore` их отсекает).

**Способ А — через интерфейс (проще):**

1. Распакуйте `amvera-upload.zip` у себя на компьютере
2. В проекте откройте вкладку **Репозиторий → Загрузить файлы**
3. Перетащите **содержимое** распакованной папки (не саму папку) — важно, чтобы `amvera.yml` оказался в корне
4. Дождитесь загрузки

**Способ Б — через git:**

```bash
git init
git add .
git commit -m "Свадебное приглашение"
git remote add amvera <адрес репозитория из кабинета Amvera>
git push amvera master
```

Amvera сама подхватит `amvera.yml` из корня.

**Обязательно проверьте папку `public/`** — в ней должно быть 6 подпапок:

| Папка | Файлов | Что это |
|---|---|---|
| `public/photos` | 6 | Фотографии для анимации |
| `public/audio` | 1 | Фоновая музыка |
| `public/fonts` | 13 | Шрифты |
| `public/background` | 1 | Фоновое изображение леса |
| `public/og` | 1 | Превью для мессенджеров |
| `public/instructions` | 1 | Документ с этой инструкцией |

Если какой-то папки нет — при загрузке через интерфейс Amvera могла её пропустить. Загрузите недостающие файлы вручную через «Репозиторий», либо используйте вариант с git — он переносит всё гарантированно.

## Шаг 4. Проверить конфигурацию

Во вкладке **Конфигурация** должно быть:

| Параметр | Значение |
|---|---|
| Окружение | Node.JS |
| Менеджер пакетов | npm |
| Версия Node | 22 |
| Команда сборки | `npm run build` |
| Команда запуска | `npm run start` |
| Порт контейнера | 3000 |

Если Amvera подтянула значения из `amvera.yml` — ничего править не нужно.

## Шаг 5. Переменные окружения

**Обязательно:**

| Имя | Значение |
|---|---|
| `DATABASE_URL` | строка подключения из шага 1 |
| `NEXT_PUBLIC_SITE_URL` | домен приложения (шаг 7), например `https://wedding-invite-username.amvera.ru` |

**Для Google-таблицы** — одно из двух:

| Имя | Значение |
|---|---|
| `GOOGLE_SHEET_WEBAPP_URL` | ссылка `https://script.google.com/macros/s/.../exec` |

> Этот адрес вы уже получали, когда настраивали таблицу на текущем сайте. Он не изменился — возьмите тот же.
> Если не найдёте: откройте вашу Google-таблицу → **Расширения → Apps Script → Начать развёртывание → Управление развёртываниями** и скопируйте URL оттуда.
>
> **Альтернатива:** не задавайте переменную, а после деплоя откройте `https://ваш-домен/setup` и вставьте ссылку там — она сохранится в базе.

**По желанию:**

| Имя | Значение |
|---|---|
| `ADMIN_TOKEN` | любой секретный ключ. Тогда `/responses` откроется только по `?key=этот_ключ` |

Переменные добавляются в **Настройки проекта → Переменные окружения**. После их добавления Amvera сама пересоберёт приложение.

## Шаг 6. Деплой

Нажмите **Собрать и запустить**. Следите за вкладками:

- **Лог сборки** — должно завершиться успешно. Там же выполнится `drizzle-kit push`, который создаст таблицы `rsvp_responses` и `app_settings`
- **Лог приложения** — должно появиться `Ready on http://...:3000`

**Важно:** `next build` сам по себе больше не требует `DATABASE_URL` — подключение к базе создаётся лениво, при первом обращении. Это сделано специально, чтобы сборка не падала, пока база ещё не подключена.

Если в **Логе сборки** увидите `WARN: drizzle-kit push не выполнился` — таблицы не создались:
1. Откройте **Консоль** проекта
2. Выполните `npx drizzle-kit push --force`
3. Перезапустите приложение

Без этого шага анкета будет выдавать ошибку при отправке.

## Шаг 7. Домен

1. Вкладка **Домены**
2. Включите бесплатный домен Amvera (вида `ваш-проект-username.amvera.ru`) или подключите свой
3. Откройте его в браузере — должно появиться приветствие с конвертом

---

## Проверка после деплоя

- [ ] Открывается приветственный экран, страница не прокручивается до нажатия «Открыть приглашение»
- [ ] Фото появляются по бокам при прокрутке
- [ ] Играет музыка после нажатия «Открыть приглашение»
- [ ] Анкета отправляется, появляется экран «Ура, вы с нами!»
- [ ] Ответ появился в Google-таблице
- [ ] `/responses` показывает все ответы

---

## Если что-то не так

**Белая страница / 500** — смотрите **Лог приложения**. Чаще всего `DATABASE_URL` задан неверно или база не запущена.

**Ответы не попадают в таблицу** — откройте `/setup`, проверьте, что ссылка сохранена, и нажмите «Проверить связь». Должно появиться «Связь есть!».

**Нет фото / музыки** — проверьте, что папки `public/photos`, `public/audio`, `public/fonts` и `public/background` попали в загрузку. Без них сайт работает, но пустой.

**Сайт падает при отправке анкеты** — убедитесь, что `drizzle-kit push` отработал: откройте `/responses`, должна быть таблица (пустая или с ответами), а не ошибка.
